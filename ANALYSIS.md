## 1. What this project is, in one paragraph

Ane is simulating the **specular IR reflectance of a periodically-textured stainless-steel (SS) surface covered by a thin chromium-oxide (Cr₂O₃) overlayer**, using the [`rcwa`](https://rcwa.readthedocs.io/en/latest/) package (Rigorous Coupled Wave Analysis). The texture is a 1-D sinusoid extracted from AFM measurements (period ≈ 6–13 µm, peak-to-peak depth ≈ 1–3 µm). The aim is to reproduce angle-resolved FTIR reflectance spectra of laser- (or otherwise-) textured SS samples and to understand how period, depth, oxide thickness, polarisation, harmonics retained, and detector aperture affect the measured signal. This is the simulation half of a TFM (Trabajo Fin de Máster) on **selective IR absorbers / spectrally-selective surfaces** — the file paths embedded in the notebooks (`...\TFM\Ref_especular\_ane_corujo\...`) make that explicit.

## 4. The Cr₂O₃ optical model — what it actually is, and where it breaks

`datos_cromo` in [Test8_full](20260508_messages/Test8_full%20(1).ipynb) implements the dispersion model from Al-Kuhaili & Durrani (2007), Eqs. (2)–(5):

**Refractive index — single-oscillator (Wemple–DiDomenico):**

```
n(E) = √( 1 + E₀·E_d / (E₀² − E²) )
```

With (E₀ = 5.13 eV, E_d = 19.2 eV) for HS films. As λ → ∞ (E → 0), n → √(1 + E_d/E₀) = √(1 + 19.2/5.13) ≈ **2.177**, which matches [calientes_cromo.csv](20260508_messages/calientes_cromo.csv) at the long-wavelength end (n ≈ 2.179 at λ = 25 µm). Sanity check ✅.

**Extinction coefficient — sub-bandgap tail:**

```
k(λ) = a₀ + a₁/λ + a₂/λ²        (Eq. 5 in the paper)
```

with (a₀ = 0.010, a₁ = −0.04121, a₂ = 0.041509) for HS. The paper fitted this to **transmittance data on 300–2500 nm = 0.3–2.5 µm**.

> ⚠️ **Major physical caveat (severity: HIGH).** Ane is sampling this model on **3–25 µm**, which is **entirely outside the fitted range — by an order of magnitude in λ**. In particular:
>
> - At λ ≫ λ_fit, Eq. (5) gives an essentially constant k(λ) ≈ a₀ + tiny corrections — the values in [calientes_cromo.csv](20260508_messages/calientes_cromo.csv) drift only from k ≈ 0.018 (3 µm) to k ≈ 0.029 (25 µm). Smooth, featureless.
> - **Real Cr₂O₃ has strong lattice (phonon) absorption** in the mid- and far-IR — Reststrahlen-type Cr–O bands roughly between 12 and 25 µm (depending on phase, density, defects). The single-oscillator + sub-bandgap-tail model **contains zero phonon physics**. So the simulated mid-IR Cr₂O₃ behaves like a near-lossless dielectric of n ≈ 2.18, k ≈ 0.02–0.03. That can substantially under-predict absorption in any IR band where phonons dominate.
> - **Recommendation:** for any spectrum extending past ~5 µm, replace this k(λ) with literature ε(ν̃) tables (Palik, refractiveindex.info, or a tabulated phonon model — Lorentz oscillators centred on the principal Cr–O modes). This is the single highest-leverage upgrade in the whole pipeline.

The "frío" (RS) parameter set lives in [indices_cromo.csv](20260508_messages/indices_cromo.csv) (n_∞ ≈ 1.92, ie. lower density / more porous film, consistent with the paper's XPS finding that RS films are more porous and stoichiometric). The notebook only documents the "caliente" parameters; the cold ones are presumably also from the paper but I cannot see them in the provided 3 pages — Ane should commit them next to `datos_cromo`.

## 5. The SS permittivity file — header is wrong

[SS_letter (1).csv](20260508_messages/SS_letter%20(1).csv) is labelled `wavenumber, n, k` but the column values are **complex permittivity (ε′, ε″), not refractive index**. Evidence:

| ν̃ (cm⁻¹) | "n" | "k" | If interpreted as (n, k) | If interpreted as (ε′, ε″) |
|---|---|---|---|---|
| 400 | −73.4 | 839 | nonsense (n cannot be < 0) | ε′ = −73, ε″ = 839 → free-electron-dominated metal in far IR ✅ |
| 7000 | 2.58 | 9.78 | unusual but not impossible | ε′ = 2.58, ε″ = 9.78 → n ≈ 2.5, k ≈ 1.9 ✅ for SS at 1.4 µm |

Ane's simulation **uses them correctly as permittivity**:

```python
ss_permittivity = {ww: complex(p1, p2) for ...}        # (ε′ + iε″) reading
permittivity = complex(permittivity.real, -permittivity.imag)   # flip to ε = ε′ − iε″ (engineering, e^{−iωt})
metal_layer = Layer(er=permittivity, ...)              # er = ε
```

So the science is right, only the header is misleading. **Action:** rename the columns to `wavenumber, eps_real, eps_imag` (or distribute a duplicate with corrected headers) so that anyone reading `SS_letter (1).csv` cold doesn't mistake it for (n, k).

## 6. Issues catalogued (severity: HIGH / MED / LOW)

### 6.1  `'./SS_letter.csv'` ≠ `'SS_letter (1).csv'` — **HIGH** (the notebook won't run)
Cell that reads SS data uses `pd.read_csv('./SS_letter.csv', sep=',')` but the file in the folder is `SS_letter (1).csv`. **Fix:** rename or update the read path. Recommend renaming the file to drop the `(1)` and the space.

### 6.2  `datos_cromo` always overwrites `calientes_cromo.csv` — **MED**
The function hard-codes the output filename. So the cell that "generates the cold one" (which Ane mentions exists) will silently clobber the hot one. Either (a) parametrise the filename, or (b) split into `datos_cromo_caliente()` / `datos_cromo_frio()`.

### 6.3  Cr₂O₃ model extrapolated 10× past its fit range — **HIGH (physics)**
See §4. Phonon absorption in Cr₂O₃ in the mid-IR is missing. This dominates wherever the spectrum overlaps the Reststrahlen band of the oxide.

### 6.4  Oxide skin is a vertical band, not a normal-to-surface coating — **MED (physics)**
[Test8_full (1).ipynb](20260508_messages/Test8_full%20(1).ipynb), `discretize_rugosity_with_oxide`, builds the oxide as a vertical band of thickness `oxide_thickness` measured along z, applied above the local metal column:

```python
oxide_threshold = z_level + oxide_thickness / total_height
oxide_idx = df.index[(df_norm > z_level) & (df_norm <= oxide_threshold)].tolist()
permitivity_matrix[-i][oxide_idx] = oxide_perm
```

For a sinusoid with A = 1.5 µm and λ = 12.9 µm, the surface slope reaches |dy/dx|_max = 2π·A/λ ≈ 0.73, i.e. ≈ 36° from horizontal at the steepest points. A real oxide growing perpendicular to the surface would have a *vertical* extent of `t_oxide / cos(36°) ≈ 1.24 · t_oxide` on the slopes. So the current code **under-represents the optical path through oxide on the slopes by up to ~25%**. For a thick oxide (0.5 µm) this matters; for a thin one (0.05 µm) it's negligible.

**Fix sketch:** for each x-pixel, compute local slope from `np.gradient(df['y'], df['x'])`; expand the band by `1/cos(arctan(slope))` (clamp at e.g. 60°). 6-line patch.

### 6.5  Modified solver — exit-angle tracking is approximate for 2-D and edge-of-cone — **MED**
In Ane's `solver.py` (in [the archive](20260508_messages/ane-thread-archive-2026-05-08.md), `_rt_quantities`):

```python
k_transverse = np.sqrt(Kx_diag**2 + Ky_diag**2)
self.theta_orders = np.rad2deg(np.arcsin(np.clip(np.real(k_transverse) / n_inc, -1, 1)))
```

Three concerns:

1. **Evanescent orders** (where `k_transverse > k0·n_inc`, ie. `k_transverse / n_inc > 1` in the normalised units) are clamped to ±90°, but they should be **excluded** from the detected sum, not lumped in. They carry zero R anyway in the propagating sense, so the practical effect is small, but the bin is wrong.
2. **2-D gratings**: the `arcsin(√(K_x²+K_y²)/n_inc)` collapses two angles into one polar angle. The detector cone is then implicitly rotationally symmetric around the surface normal. For a 1-D grating with `phi=89°` (single diffraction plane) this is fine. For a 2-D grating it conflates orders that are *azimuthally* offset from the specular direction. Worth a comment in the code.
3. **`theta_specular`**: code uses `self.source.theta` directly. For 1-D RCWA this is right (specular order m=0 is at θ_in, only φ flips). For 2-D it's still right *for the polar angle*, but the azimuth is implicit.

### 6.6  β semantics — half-angle vs. full-cone — confirm before publishing — **LOW**
`mask = np.abs(self.theta_orders - np.rad2deg(theta_specular)) <= (beta / 2)` → β is the **full** detector cone diameter, half-aperture = β/2. The CSV filenames in `Representacion.ipynb` (`LX_0.2_6.35.csv`, `LX_50.0_6.35.csv`) reference β = 0.2° (truly specular), 10°, 15°, 20°, 30°, 50°. If anywhere else in the writeup β refers to half-aperture, those numbers will be off by 2×. Mention which convention is used in the figure caption.

### 6.7  Substrate is **not** semi-infinite — **MED (modelling)**
The current stack has `transmission_layer = Layer(er=1.0, ur=1.0)` (vacuum behind the SS), and the SS slab is a finite 200 µm layer in the *internal* layers list. So the simulated geometry is **air | grating | 200 µm SS | air**. Light that gets through the SS slab exits into vacuum, which is not what an FTIR measurement of a thick SS plate sees.

The right thing for a thick (effectively semi-infinite) SS plate is `transmission_layer = Layer(er=ε_SS(λ), ur=1.0)`. The `Representacion.ipynb` cell with the `aire/capas/metal/aire`, `aire/capas/metal`, `aire/capas/aire` triptych shows Ane is already aware. **Recommendation:** make the *truly* semi-infinite version the production one (set `transmission_layer.er = ε_SS(λ)`, drop the explicit 200 µm layer), and keep the slab variant only for diagnostics.

At λ where SS k ≳ 0.5 (most of the IR), 200 µm is many skin depths and the finite-slab artefact is small. Below that — and at thinner samples — it isn't.

### 6.8  Plotting helpers use Windows paths and broken closures — **HIGH for portability**
[Representacion.ipynb](20260508_messages/Representacion.ipynb) `get_una` / `get_prom`:

```python
ruta = r'C:\\Users\usuario\Desktop\TFM\Ref_especular\_ane_corujo'
muestra = f"{period}-{prof}"          # ← uses module-level `period`/`prof`, not the args
```

Two bugs:
1. Hard-coded Windows path won't work on macOS or Linux.
2. The function takes `(periodo, profundidad, theta, phi)` as parameters but the body uses **`period` and `prof` from the surrounding cell**, not the function arguments. This is a leaky-closure bug — works as long as the outer cell defines `period`/`prof` *and* the caller uses the same names, but breaks the moment those globals are missing or different from the args. It's silently wrong rather than loudly wrong.

**Fix:** parametrise `ruta` (e.g. `pathlib.Path(os.environ.get("REF_ESPECULAR_DIR", "..."))`), and use `periodo` / `profundidad` inside the function bodies.

### 6.9  Cosmetic: f-string missing in `_check_converged` — **LOW**
```python
raise RuntimeError('Exceeded maximum number of iterations {self.max_iters} ...')
```
Missing `f`. The error message will literally print `{self.max_iters}` rather than the value. One-character fix.

### 6.10  Convergence study runs `harmonics = 35` in production but study reaches 51 — **LOW**
Header markdown of `Test8_full` says "*A partir de 27 armónicos; pero mejor usar 31*". Production cell uses 35. Latest `datos_oxide` study reaches 51. Reasonable — the sweep is meant to verify NA = 35 is enough; just confirm in writing that the production run converged within ~1% relative to NA = 51 across the whole 3–18 µm range.

## 7. What the data files say at a glance

```
SS_letter (1).csv:    701 rows, ν̃ ∈ [400, 7000] cm⁻¹  ⇒  λ ∈ [1.43, 25] µm
                      ε′ ∈ [−73, +2.6],  ε″ ∈ [+839, +9.8]
                      Smooth, no obvious phonon features  ⇒ likely a Drude-style fit, not raw FTIR
                      Note: header lies (says n,k, is ε′,ε″) — see §5.

indices_cromo.csv     [≈ RS, paper's "unheated substrate" film]:
                      200 rows, λ ∈ [3, 25] µm
                      n_∞ ≈ 1.920    (so E_d/E₀ ≈ 2.69)
                      k(λ=14 µm) ≈ 0.0277
                      k(λ=25 µm) ≈ 0.0291

calientes_cromo.csv   [≈ HS, paper's "300 °C substrate" film]:
                      200 rows, λ ∈ [3, 25] µm
                      n_∞ ≈ 2.178    (so E_d/E₀ ≈ 3.74, matches paper's HS parameters E₀=5.13, E_d=19.2)
                      k(λ=14 µm) ≈ 0.0072
                      k(λ=25 µm) ≈ 0.0044
```

**Verified `diff`:** the two files are *not* identical (good). The labelling is consistent with the paper's main claim that **n_HS > n_RS** (2.18 > 1.92). Note however a subtlety worth understanding:

> 🧠 **Subtlety to flag in the writeup.** The paper's abstract says "*the refractive index, the extinction coefficient and the optical bandgap all increased with substrate temperature*". That claim is about k **near the absorption edge**, where it actually matters for transmittance. In the **deep sub-bandgap tail** sampled by these CSVs (λ = 3–25 µm, hf ≪ E_g ≈ 3 eV), the trend reverses: **k_RS > k_HS** in [indices_cromo](20260508_messages/indices_cromo.csv) vs [calientes_cromo](20260508_messages/calientes_cromo.csv). This is physically plausible — RS films are amorphous and porous (XPS shows higher H/L oxygen ratio = more adsorbed water/defects), so they carry a stronger defect-absorption tail in the deep IR — but the (a₀, a₁, a₂) tail coefficients are an *empirical interpolation* of transmittance data taken on 0.3–2.5 µm; **at 3–25 µm we are extrapolating a defect-tail model into a regime dominated by phonons that the model does not contain** (see §4 / §6.3). So the relative ordering of k_RS vs k_HS at long λ is *an artefact of the parametrised tail*, not a measured property. Treat it as such.
